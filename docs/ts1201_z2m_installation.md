# TS1201 Zigbee2MQTT 1.3.0 试点安装

适用精确指纹 `TS1201 / _TZ3290_qazgdsae`。这是带本地码库和命名学习的外部转换器方案，工程人员部署后可交客户试用。设备一次只能加入一套 Zigbee 网络；使用 ZHA 的设备不能同时在 Z2M 操作。

## 安装及更新

下载并解压本仓库，以下文件均从解压后的仓库目录取得：

- `zemismart_ts1201_ir.mjs`：外部转换器。
- `ts1201-ir-codebooks.json`：完整本地码库，必须与转换器放在同一目录。
- `ts1201-ir-codebooks-LICENSE.txt`：码库许可证，随码库保留。

不要只下载一个 `.mjs` 文件。仓库根目录的上述三个文件构成同一套 1.3.0 运行文件。

实际加载验证环境为 Z2M 2.14.1 / zigbee-herdsman-converters 26.105.0；26.105.0 和 26.109.0 均完成软件回归。其他版本需单独验证；本包不要求为了基础停止学习修复而立即升级全套系统。

1. 备份 Z2M 数据目录和现有同名外部转换器。设备元数据中包含已确认码库及学习键，不能只备份转换器文件代替数据备份。
2. 在实际 Z2M 数据目录的 `external_converters/` 中放入 `ts1201-ir-codebooks.json` 和 `ts1201-ir-codebooks-LICENSE.txt`。保留原文件名；旧快配小码库不具备完整日常控制表。
3. 使用 Z2M 前端 Settings → Dev console → External converters 保存完整 `zemismart_ts1201_ir.mjs`，由运行中的服务热加载。若该版本禁用了外部 JavaScript，需由工程人员按官方说明配置。
4. 确认服务报告转换器加载成功，目标设备厂家和型号均匹配。仅复制文件不代表已加载。
5. 从旧版升级后，读取一次虚拟按键库状态：在界面使用读取入口，或向实际 `BASE_TOPIC/DEVICE_NAME/get` 发送 `{"ir_key_status":""}`。这是本地状态读取，不发送红外；用于让旧版保存记录和过期控件完成初始化。
6. 开启既有 Home Assistant MQTT discovery 后检查对应设备页面；空键库先显示名称与学习入口，保存后的命名按钮和适用的管理控件按状态出现。

码库和转换器应作为完整版本交付。更新过程不应开启配对、自动匹配或发送红外。升级前先确认保存或放弃待保存的捕获，再结束正在进行的学习或发送。

## 使用

- [按品牌匹配](ts1201_z2m_customer_guide.md#空调品牌匹配)：红外盒对准家电后，开始匹配会发送第一套试机码；有实际响应才确认。重复确认同一已保存结果不会覆盖后续控制设置。
- [空调日常控制](ts1201_z2m_customer_guide.md#日常空调控制)：仅提供当前码库支持的模式、温度和风速，面板是命令估计。
- [自学习命名按键](ts1201_z2m_customer_guide.md#自学习遥控按键)：命名→开始学习→原遥控器按键→完整捕获→确认保存→发送并观察家电。需要结束时用“停止按键学习”；失败后重试停止，不把失败视为已停止。

如果使用原始码或其他无法确定空调完整状态的命令，`ac_estimate_stale` 和控制状态会提示估计可能过期。传输完成也不能替代家电物理响应。

## 回滚和验收

需要回退时，恢复整套旧转换器、旧码库和许可证，再通过相同前端入口热加载旧转换器。恢复配置文件不等于恢复学习键库；数据损坏时使用升级前的完整 Z2M 备份，避免覆盖后来新增的有效按键。

验收分别记录：模块加载与准确指纹、HA发现/控件、命令完整传输、家电响应、已保存键重载/重启后可用。单台空调的一次制冷响应不覆盖全部码库和档位。

本配置不包含客户学习码、账号或固定主机地址。上游基础停止学习修复已合并；本配置新增匹配、命名学习与面板功能仍属于自定义试点方案。完整验证范围见[验证记录](ts1201_validation.md)。
